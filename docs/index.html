🏗 Platform Creation Process & Architecture

How the Dadiwoo Cyber Range was architected and built for virtualized networking laboratories.

1. System Design & Objectives

The Dadiwoo Cyber Range platform was engineered to address the resource constraints of virtualized network simulators (GNS3, EVE-NG, PNETLab, Proxmox). Traditional vulnerable VMs (like Metasploitable) consume 2GB–4GB RAM each, making multi-target network topologies prohibitively heavy. Dadiwoo microservices are designed to consume less than 60MB RAM per container while providing authentic offensive and defensive security exercises.

2. Component Creation Breakdown

  • Manager Control Plane (`manager/`): Developed as an asynchronous FastAPI application that interfaces with SQLite to maintain registry states, custom port bindings, difficulty levels, and environment purpose toggles.
  • Embedded UDP Mini DNS (`dns/mini_dns.py`): Built using standard UDP sockets and `dnslib` to respond to DNS A-record queries for `*.lab` domains directly, automatically syncing `/etc/hosts` formats for local resolvers.
  • Microservice Security Targets (`labs/`): Constructed using Python FastAPI, Jinja2 templates, and lightweight SQLite backends. Each lab implements standard OWASP vulnerability classes alongside business logic flaws.
  • Orchestrator Shell (`start_labs.sh`) & Container Engine (`docker-compose.yml`): Enables native execution directly on Ubuntu Server host processes or full containerization via Docker Compose.

💻 Programming Languages & Frameworks Stack

Every component of the platform relies on modern, lightweight, standard technologies.

🐍

Python 3.12

Core backend language powering the Control Plane, Mini DNS Server, and all 6 microservice application backends.

⚡

FastAPI & Uvicorn

High-performance ASGI web framework providing non-blocking asynchronous REST endpoints and rapid HTML template rendering.

🗄️

SQLite 3

Zero-configuration embedded relational database engine utilized by each microservice and the central manager for persistent storage.

🎨

HTML5 / CSS3 / JavaScript

Modern dark-mode UI styled with Flexbox/CSS Grid, Inter & JetBrains Mono typography, and asynchronous Fetch API for dynamic state updates.

📡

dnslib (UDP DNS)

Python DNS encoding and decoding library used to parse binary DNS wire formats over UDP socket port 5353.

🐳

Docker & Docker Compose

Multi-stage containerization configuration isolating services into dedicated Linux network namespaces.

🧪

Pytest & TestClient

Automated regression test suite covering all REST endpoints, database queries, and environment state toggles.

🌐

GNS3 / EVE-NG Integration

Native support for virtualized routers (MikroTik, Cisco), firewalls (pfsense, OPNsense), and network monitoring tools (Zabbix, Wazuh).

🌐 Resolving `.lab` Domain Names

To enable instant domain resolution for atm.lab, bank.lab, isp.lab, school.lab, shop.lab, and mobile.lab:

Option 1: Add the `/etc/hosts` Line (Recommended)

Copy the exact line provided on the Dadiwoo Control Plane Dashboard (`http://:9000`):

127.0.0.1 atm.lab bank.lab isp.lab school.lab shop.lab mobile.lab wave.lab snmp.lab ssh.lab apiwarehouse.lab

Append it to your machine's `/etc/hosts` file:

echo "127.0.0.1 atm.lab bank.lab isp.lab school.lab shop.lab mobile.lab wave.lab snmp.lab ssh.lab apiwarehouse.lab" | sudo tee -a /etc/hosts

🐉 Penetration Testing & OSINT Reconnaissance

A. Port Scanning (Nmap)

nmap -p 8080-8088,9000,5353,2222,16161 -sV <UBUNTU_VM_IP>

B. OSINT & Reconnaissance Analysis (Recon-ng, SpiderFoot, WhatsMyName)

When conducting Open Source Intelligence (OSINT) testing on microservice cyber ranges:

  • WhatsMyName: Performs username enumeration across 600+ public SaaS platforms (e.g., GitHub, Twitter, Reddit). For local cyber ranges, username targets (`STD-1001`, `admin`) can be analyzed against endpoint lookup APIs (`/api/v1/users/`).
  • Recon-ng: Modular OSINT framework querying WHOIS, Shodan, and DNS records. When attacking GNS3/EVE-NG lab subnets, configure Recon-ng modules to query the embedded Mini DNS server (`<UBUNTU_VM_IP>:5353`).
  • SpiderFoot: Scrapes web server headers (`Uvicorn/FastAPI`), subdomains, and endpoint URLs across local microservices (`http://<UBUNTU_VM_IP>:8080-8085`) to map software stacks and contact metadata.
